# cn-app-launch-compliance（中国大陆移动 App 上线合规）

一个可复用的 Agent **Skill**：把"在中国大陆合规上线一个移动 App（Android / iOS / 小程序，含 AI 能力）"拆成可单独执行、且能部分自动化的阶段，并严格遵守一条铁律：**Agent 绝不代替你做实名、签约、人脸核验或提交政府 / 平台表单。** 它只负责起草材料、扫描代码行为、列出有序待办、运行只读体检脚本，并把"必须由人来做"的事清清楚楚排出来。

## 它能做什么

- 走完 **9 个阶段**：主体一致性 → 域名与备案 → 服务器与网络 → 隐私合规 → 支付接入 → 应用商店上架 → 短信 → 生成式 AI 备案 → 上线前体检。
- 强制执行**最高优先级原则——主体一致性**：域名实名、ICP 备案、公安备案、商户（微信 / 支付宝）、小程序、短信资质、软著 / 商店开发者，主体必须统一（通常为企业营业执照主体）。
- 明确标注**哪些可由 Agent 自动化**、**哪些必须由你本人完成**（实名 / 签约 / 人脸核验 / 表单提交）。
- 汇总**高频驳回原因**及修复方式与官方来源链接。
- 运行一个**只读合规体检脚本**检查公开 URL。

## 何时使用

- "国内上线" / "上架应用商店" / "接微信支付 / 支付宝" / "做备案" / "合规发布"
- 准备在国内发布含 AI 能力的 App（涉及算法 / 大模型备案）
- 需要一份国内上线清单、驳回排查或上线前体检

## 安装

把 skill 文件夹复制到 Agent 的 skills 目录：

```bash
# 项目级
cp -r cn-app-launch-compliance <项目>/.workbuddy/skills/

# 用户级（全局）
cp -r cn-app-launch-compliance ~/.workbuddy/skills/
```

Agent 在你提出国内上线 / 合规相关需求时触发。

## 使用

1. **主体先行。** 先确认统一主体，再推进任何步骤；主体不一致会在备案 / 签约 / 审核环节连环失败。
2. **按阶段顺序推进**（见 `references/checklist.md`）。Agent 负责起草、扫描、列清单；你负责实名 / 签约 / 提交。
3. **对线上 URL 跑只读体检**：

   ```bash
   python scripts/compliance-check.py https://your-site.example.com --timeout 10
   ```

   它**只读取、不修改**任何内容，检查：
   - 是否启用 HTTPS
   - 是否含 ICP 备案号（如 `京ICP备XXXXXXXX号`）
   - 是否含公安备案号（如 `京公网安备XXXXXXXX号`）
   - 是否有隐私政策入口
   - 是否检测到境外依赖（Google Fonts / Analytics / gstatic / firebase / cloudflare）
   - 是否含 AI 生成内容标识（仅当 App 提供生成式 AI 时相关）

   输出为 JSON 报告；任一必检项 FAIL 时退出码为 `1`。
4. **修复 FAIL 项**：回到对应阶段修复后，复测直到通过。

## Agent / 人 分工（始终遵循）

| 类型 | Agent 可做 | 人必须做 |
|---|---|---|
| 起草 | 隐私政策 / 协议初稿、备案信息表、商店文案、短信模板 | — |
| 代码 | 去境外依赖、回调验签、footer 备案号、AI 标识 | — |
| 扫描 | 权限 / SDK 收集行为、体检脚本 | — |
| 资质 | — | 实名、签约、对公账户、人脸核验 |
| 提交 | — | 政府 / 平台表单、审核应对 |

## 重要说明

- 本 Skill **不编造费用与时效**，只引用官方页面已写明的数据，不确定处标注"⚠️ 以官方最新公示为准"。
- **绝不替代实名或签约**；体检脚本严格只读。
- 条款与要求以工信部、公安部、网信办、微信 / 支付宝开放平台官方文档为准，并注明核对日期。
