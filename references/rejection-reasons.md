# 高频驳回原因与修复

## 备案类
| 驳回原因 | 修复 |
|---|---|
| 主体信息不一致（域名实名 ≠ 备案主体） | 统一主体，重提 |
| 网站/App 名称含敏感或违规词 | 改名后重提 |
| 备案信息中服务内容与实际不符 | 如实填写，补充说明 |
| 公安备案未填接入地/负责人信息 | 补全全国互联网安全管理服务平台信息 |
| 24h 内未做短信核验 | 留意备案手机号短信，及时核验 |

## 支付类（微信/支付宝）
| 驳回原因 | 修复 |
|---|---|
| 缺少对公账户 / 账户名与主体不一致 | 使用与商户主体一致的对公账户 |
| 经营类目与营业执照范围不符 | 调整类目或补充资质 |
| 回调地址不可达 / 验签失败 | 部署可达 HTTPS 回调，校验签名逻辑 |
| 未配置退款/账单 | 补齐支付闭环能力 |

## 应用商店类
| 驳回原因 | 修复 |
|---|---|
| 缺少软著 / 著作权证明 | 提前申请软著（周期较长，尽早） |
| 隐私政策链接打不开或不完整 | 修复隐私政策页，覆盖收集项 |
| 过度申请权限（如非必要定位/通讯录） | 按最小必要原则收敛权限 |
| 截图与实机不符 / 含竞品水印 | 替换为真实无遮挡截图 |
| 应用名称/图标侵权 | 改名换标，规避商标 |

## 短信类
| 驳回原因 | 修复 |
|---|---|
| 签名与企业名不一致 | 使用营业执照全称或简称（需一致） |
| 模板含营销/外链违规词 | 按平台模板规范改写 |
| 资质未实名 | 完成企业实名后重提 |

## 通用红线
- 不伪造备案号 / 不挂靠不一致主体。
- 不隐瞒个人信息收集行为（与隐私政策必须一致）。
- 含 AI 能力必须履行备案/标识义务，不得规避。
